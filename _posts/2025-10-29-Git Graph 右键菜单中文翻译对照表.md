## Git Graph 右键菜单中文翻译对照表（VSCode）

Git Graph 是 VS Code 中非常实用的 Git 可视化插件，右键菜单中有很多常见操作。下面整理一份中文对照表，方便快速理解和查找。

---

### 一、提交节点右键（单个 Commit）

| 英文菜单                         | 中文翻译                       | 说明                                                                     |
| -------------------------------- | ------------------------------ | ------------------------------------------------------------------------ |
| Checkout Commit                  | 检出到此提交                   | 临时切换到这个提交对应的快照，常见于查看历史版本，可能进入游离 HEAD 状态 |
| Create Branch from Commit        | 从此提交新建分支               | 基于当前提交创建新分支                                                   |
| Create Tag from Commit           | 从此提交新建标签               | 给当前提交打一个标签                                                     |
| Reset Current Branch to Here     | 将当前分支重置到此提交         | 把当前分支回退到这个提交位置                                             |
| Soft Reset                       | 软重置                         | 仅移动 HEAD，改动保留在暂存区                                            |
| Mixed Reset                      | 混合重置                       | 仅移动 HEAD，并把暂存区清空，改动回到工作区，默认行为                    |
| Hard Reset                       | 硬重置                         | 彻底丢弃当前分支后续改动，危险操作                                       |
| Cherry Pick Commit               | 拣选提交                       | 把当前提交复制到当前分支                                                 |
| Revert Commit                    | 反向提交                       | 生成一条反向提交来撤销当前更改，比较安全，可推送到远程                   |
| Merge Commit into Current Branch | 将此提交所在分支合并到当前分支 | 把某个提交的分支内容合并进当前分支                                       |
| Squash Commits                   | 压缩提交                       | 将多条提交合并成一条提交                                                 |
| Copy Commit Hash                 | 复制提交哈希值                 | 复制当前提交的唯一标识                                                   |
| View Commit Details              | 查看提交详情                   | 查看该提交的详细信息、文件差异等                                         |
| Open File(s)                     | 打开变更文件                   | 直接打开该提交中的改动文件                                               |
| Compare with Current             | 和当前工作区对比差异           | 对比当前提交与本地工作区的差异                                           |

### 二、分支名右键（本地 / 远程分支）

#### 1. 本地分支 Local

| 英文菜单                               | 中文翻译               | 说明                                      |
| -------------------------------------- | ---------------------- | ----------------------------------------- |
| Checkout Branch                        | 切换到该分支           | 切换当前工作分支                          |
| Rename Branch                          | 重命名分支             | 修改分支名称                              |
| Delete Branch                          | 删除本地分支           | 删除当前本地分支                          |
| Merge into Current Branch              | 合并该分支到当前分支   | 把目标分支内容合并到当前分支              |
| Rebase onto Current Branch             | 变基到当前分支         | 把当前分支的提交重新挂到另一个分支之上    |
| Rebase Current Branch onto This Branch | 将当前分支变基到该分支 | 让当前分支基于这个分支重新变基            |
| Push Branch                            | 推送分支到远程         | 上传本地分支到 GitHub / GitLab 等远程仓库 |
| Publish Branch                         | 发布本地新分支到远程   | 首次推送本地新分支到远程                  |
| Set Upstream                           | 设置上游远程分支       | 绑定本地分支和远程分支的跟踪关系          |
| Unset Upstream                         | 解除上游绑定           | 取消本地分支与远程分支的跟踪关系          |

#### 2. 远程分支 Remote

| 英文菜单                 | 中文翻译                   | 说明                               |
| ------------------------ | -------------------------- | ---------------------------------- |
| Fetch Remote             | 拉取远程更新               | 下载远程仓库最新变更，但不合并     |
| Pull into Current Branch | 拉取远程代码合并到当前分支 | 把远程改动拉取并合并到当前分支     |
| Delete Remote Branch     | 删除远程分支               | 删除远程仓库中的分支               |
| Checkout Remote Branch   | 检出远程分支到本地         | 创建本地跟踪分支并切换到该远程分支 |

### 三、合并 / 冲突相关

| 英文菜单        | 中文翻译           | 说明                             |
| --------------- | ------------------ | -------------------------------- |
| Abort Merge     | 中止合并           | 取消当前正在进行的合并操作       |
| Continue Merge  | 解决冲突后继续合并 | 在合并冲突解决完成后继续执行合并 |
| Abort Rebase    | 中止变基           | 终止当前变基操作                 |
| Continue Rebase | 解决冲突后继续变基 | 在冲突解决后继续变基             |

## 实用建议

1. 如果只是想“撤销最近一次提交，但保留修改”，优先考虑 `Soft Reset` 或 `Mixed Reset`。
2. 如果你确定不再需要这些改动，才用 `Hard Reset`，因为它会直接丢失未提交内容。
3. 对于已经推送到远程的错误提交，通常更推荐 `Revert Commit`，比直接重置更安全。
4. `Rebase` 适合整理提交历史；`Merge` 适合保留分支演进关系，团队协作时通常更容易理解。

## 一句话总结

Git Graph 的右键菜单，本质上就是把 Git 常用命令做成了图形化操作：提交管理、分支切换、远程同步、合并与冲突处理都能在界面上直接完成。

如果你经常使用 Git，熟悉这些中文对应词，会让你在 VS Code 里操作得更顺手。
